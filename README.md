# Library Management REST API

Software Engineering Reference Lab project using Java 17, Spring Boot 3.5.16,
Maven, Spring Web, Spring Data JPA, Bean Validation, H2, and SpringDoc OpenAPI.

## Requirements

- JDK 17
- Apache Maven (verify with `mvn -version`)

## Build and test

```powershell
mvn clean verify
```

## Run

```powershell
mvn spring-boot:run
```

The server listens on http://localhost:8080. Stop it with Ctrl+C.
On startup, `data.sql` inserts 5 books and 3 members.

## Lab 1 endpoints

| Method | Path | Result |
|--------|------|--------|
| GET | `/books` | All books (200) |
| GET | `/books/{id}` | One book (200 or 404) |
| POST | `/books` | Create book (201 with Location header) |
| PUT | `/books/{id}` | Replace book fields (200 or 404) |
| DELETE | `/books/{id}` | Delete book (204 or 404) |
| GET | `/members` | All members (200) |
| GET | `/members/{id}` | One member (200 or 404) |
| POST | `/members` | Create member (201 with Location header) |

Invalid request fields return 400. IDs are generated by the database; IDs in
request bodies are ignored. PUT requires the book's required fields and updates
the record identified by the URL, returning 404 if it does not exist.
Books default to available; members default to active with today's membership
date when those fields are omitted. Dates use ISO `YYYY-MM-DD` format.

Try http://localhost:8080/books and http://localhost:8080/members for sample JSON.
Interactive API documentation: http://localhost:8080/swagger-ui.html.
OpenAPI JSON: http://localhost:8080/v3/api-docs.

Example PowerShell request:

```powershell
$book = @{
    isbn = '978-0-00-000001-1'
    title = 'Example Book'
    author = 'Example Author'
    genre = 'Programming'
    publishedYear = 2026
    available = $true
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/books -ContentType application/json -Body $book
```

## Local database

Open http://localhost:8080/h2-console while the application is running:

- JDBC URL: `jdbc:h2:mem:librarydb`
- Username: `sa`
- Password: leave blank

The in-memory database resets when the application stops. The H2 console and
empty password are intended for local lab development.

## Architecture and structure

- `src/main/java/com/example/library/LibraryApiApplication.java`: Spring Boot entry point;
  its package is the root for component, entity, and repository scanning.
- `entity`: `Book`, `Member`, and `Borrowing` map Java objects to database tables.
  `Borrowing` uses two `@ManyToOne` relationships, ISO dates via `LocalDate`,
  and `BigDecimal` for exact monetary amounts. There are no reverse collections,
  avoiding recursive JSON serialization.
- `repository`: one `JpaRepository<Entity, Long>` per entity. Spring Data supplies
  CRUD implementations, so there is no handwritten SQL for normal API requests.
- `controller`: maps HTTP requests to repository operations, validates request
  bodies with `@Valid`, and selects HTTP response statuses. Dependencies use
  constructor injection. Lab 1 keeps simple CRUD in controllers; a service layer
  for borrowing rules belongs to Lab 2.
- `src/main/resources/application.properties`: application and H2 settings
- `src/main/resources/data.sql`: reproducible sample data, loaded after JPA schema creation
- `src/test/java/com/example/library`: startup, persistence, endpoint, validation,
  and OpenAPI checks; transactional endpoint tests roll back their changes
- `reports/lab1-report.md`: Lab 1 reflections and verification evidence
- `docs/lab1-walkthrough.md`: guided code review and manual verification

Request flow: HTTP JSON -> controller -> repository -> H2; results return as JSON.
The model and endpoints cover Lab 1 only. Borrowing workflows, reservations,
deployment, and code metrics are introduced by later labs.
