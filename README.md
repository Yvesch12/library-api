# Library Management REST API

Software Engineering Reference Labs 1-8 using Java 17, Spring Boot 3.5.16,
Maven, Spring Web, Spring Data JPA, Bean Validation, H2, and SpringDoc OpenAPI.

## Requirements

- JDK 17
- Apache Maven (verify with `mvn -version`)

## Build and test

```powershell
mvn clean verify
```

## Run

```powershell
mvn spring-boot:run
```

The server listens on http://localhost:8080. Stop it with Ctrl+C.
On startup, `data.sql` inserts 5 books and 3 members.

## Book and member endpoints

| Method | Path | Result |
|--------|------|--------|
| GET | `/books` | All books (200) |
| GET | `/books/{id}` | One book (200 or 404) |
| POST | `/books` | Create book (201 with Location header) |
| PUT | `/books/{id}` | Replace book fields (200 or 404) |
| DELETE | `/books/{id}` | Delete book (204 or 404) |
| GET | `/members` | All members (200) |
| GET | `/members/{id}` | One member (200 or 404) |
| POST | `/members` | Create member (201 with Location header) |

Invalid request fields return 400. IDs are generated by the database; IDs in
request bodies are ignored. PUT requires the book's required fields and updates
the record identified by the URL, returning 404 if it does not exist.
Books default to available; members default to active with today's membership
date when those fields are omitted. Dates use ISO `YYYY-MM-DD` format.

Try http://localhost:8080/books and http://localhost:8080/members for sample JSON.
Interactive API documentation: http://localhost:8080/swagger-ui.html.
OpenAPI JSON: http://localhost:8080/api-docs (changed in Lab 4).
Health check: http://localhost:8080/actuator/health.

## Borrowing and reservation endpoints

| Method | Path | Request / behavior |
|---|---|---|
| POST | `/borrowings` | `{"bookId":1,"memberId":1}`; marks book unavailable, due in 14 days |
| PUT | `/borrowings/{id}/return` | Records return and fine at EUR 0.50/day overdue |
| GET | `/members/{id}/borrowings` | Active borrowings only |
| POST | `/reservations` | `{"bookId":1,"memberId":2}`; unavailable book and active member required |
| PUT | `/reservations/{id}/cancel` | Cancels an active reservation |
| GET | `/members/{id}/reservations` | All statuses, ascending reservation ID |

Creates return 201; reads/updates return 200. Missing resources return 404,
invalid input 400, and business conflicts 409. Error bodies include `error`,
`timestamp`, and `fields`. Duplicate returns/reservations are rejected.
Borrowing and reservation DTOs expose relation IDs rather than nested entities.

Example PowerShell request:

```powershell
$book = @{
    isbn = '978-0-00-000001-1'
    title = 'Example Book'
    author = 'Example Author'
    genre = 'Programming'
    publishedYear = 2026
    available = $true
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8080/books -ContentType application/json -Body $book
```

## Architecture and structure

- `src/main/java/com/example/library/LibraryApiApplication.java`: Spring Boot entry point;
  its package is the root for component, entity, and repository scanning.
- `entity`: `Book`, `Member`, and `Borrowing` map Java objects to database tables.
  `Borrowing` uses two `@ManyToOne` relationships, ISO dates via `LocalDate`,
  and `BigDecimal` for exact monetary amounts. There are no reverse collections,
  avoiding recursive JSON serialization.
- `repository`: one `JpaRepository<Entity, Long>` per entity. Spring Data supplies
  CRUD implementations, so there is no handwritten SQL for normal API requests.
- `controller`: maps HTTP requests to service operations, validates request
  bodies with `@Valid`, and selects HTTP response statuses. Dependencies use
  constructor injection. All controllers use DTOs and mappers after Lab 4.
- `service`: owns transactions, lookup rules, CRUD, borrowing, returns, and reservations.
- `dto` and `mapper`: define API fields independently from persistence entities.
- `exception`: consistent shared HTTP error handling and defensive field-error copies.
- `src/main/resources/application.properties`: application and H2 settings
- `src/main/resources/data.sql`: reproducible sample data, loaded after JPA schema creation
- `src/test/java/com/example/library`: startup, persistence, endpoint, validation,
  and OpenAPI checks; transactional endpoint tests roll back their changes
- `reports/lab1-report.md`: Lab 1 reflections and verification evidence
- `docs/lab1-walkthrough.md`: guided code review and manual verification

Request flow: HTTP JSON -> DTO/controller -> service -> repository -> H2;
results return through mappers as DTO JSON.

## Analysis and regression experiments

```powershell
mvn test
mvn pmd:pmd spotbugs:spotbugs pmd:check
```

JaCoCo HTML is generated by `mvn test` at `target/site/jacoco/index.html`.
PMD XML: `target/pmd.xml`; SpotBugs XML: `target/spotbugsXml.xml`.
Measured final suite: 44 tests; overall line coverage 89.94%; service line and
branch coverage 100%. These results are checks of specified scenarios, not a
claim of complete correctness. Import-coupling/coverage summaries can be refreshed
with `python scripts/metrics.py docs/metrics.json`.

`python scripts/mutation-check.py` reproduces Lab 7's two intentional fine bugs,
requires a green baseline, and restores the original source in a finally block.
It is a local development experiment; run it without editing the same source
concurrently, then run `mvn clean verify` to rebuild the restored application.
